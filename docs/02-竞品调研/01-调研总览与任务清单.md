## 2. 调研原则与合规红线

### 2.1 记录原则

1. 只记录自己实际观察到的界面、交互与文案，不写推测。
2. 每条结论必须能回溯到证据编号（截图、录屏、时间点），无证据的观察标注「待复核」。
3. 区分三类信息并分别标注：
   - 「观察事实」：界面上直接可见。
   - 「行为推断」：由交互结果推断，例如「点击后进入队列」，需注明推断依据。
   - 「不可验证」：技术架构、算法、服务端实现、内部数据，一律不记录为事实。
4. 涉及数值的内容（倒计时、动画时长、卡牌数量、价格）必须注明采集时的具体值，不写「大约」「很快」。
5. 页面状态要覆盖：默认、加载、空、异常、断网、新用户、老用户。只记录正常路径视为未完成。

### 2.2 合规红线

1. 不下载、不截取、不复用竞品的官方美术、插画、角色、图标、音效、字体文件作为 BOMB CAT 的素材。
2. 截图仅用于内部分析，不进入对外交付物，不上传到公开渠道。
3. 不破解客户端、不抓包分析私有接口、不逆向资源包。
4. 不使用竞品商标、角色名作为 BOMB CAT 的命名或宣传语。
5. 调研结论描述「机制与体验目标」，不描述「照搬某页面布局」。

## 3. 记录字段定义

每个页面统一使用以下 9 个字段，字段含义与记录要点如下。

| 字段 | 记录要点 |
| --- | --- |
| 页面目标 | 该页面在用户旅程中承担什么任务；用户从哪来、要去哪 |
| 页面布局 | 分区结构（顶部/中部/底部/浮层）、信息层级、首屏可见内容、滚动后内容、横竖屏差异 |
| 页面元素 | 按钮、图标、文本、列表、卡片、弹窗、进度条、货币与入口；标注位置与相对大小 |
| 用户操作 | 可点击/可滑动/可长按的对象，主操作与次操作，返回路径，误触保护 |
| 页面状态 | 加载、空、正常、满员、异常、断网、维护、新用户引导、禁用态 |
| 交互反馈 | 点击反馈、转场动画、音效、震动、Toast、加载态、成功/失败提示、防重复提交 |
| 业务规则 | 从界面可验证的规则：人数限制、次数限制、冷却、消耗、解锁条件、每日重置 |
| BOMB CAT 对标建议 | 建议保留的体验目标与机制（写「要达成什么」，不写「照抄哪个控件」） |
| 原创化设计建议 | 差异化方向：叙事、视觉语言、交互隐喻、信息组织方式的替换方案 |

填写要求：每个字段至少 1 条，无内容时写「未观察到」并说明原因，不留空白。

## 5. 执行顺序建议

```
第一批（核心玩法闭环）
  EK2-01 首页和大厅 → EK2-02 模式 → EK2-03 AI 对战
  → EK2-07 牌桌 → EK2-08 卡牌交互 → EK2-09 特殊弹窗 → EK2-12 结算

第二批（联机链路）
  EK2-04 好友对战 → EK2-06 房间等待 → EK2-05 在线匹配

第三批（长线与表现）
  EK2-10 互动表情 → EK2-11 角色装扮 → EK2-13 排行榜成长
  → EK2-14 音效动画 → EK2-15 设置帮助
```

理由：第一批决定 BOMB CAT 的核心玩法能否成立；第二批决定联机架构的产品需求；第三批决定留存与完成度，且可在立项结论之后再展开。

## 6. 完成标准

一个页面视为「已完成」需同时满足：

1. 9 个字段全部填写，无空白字段。
2. 页面状态覆盖新用户、正常、加载、异常四类。
3. 至少 1 条证据编号可回溯（截图或录屏时间点）。
4. 「BOMB CAT 对标建议」写的是体验目标，可被产品与设计直接使用。
5. 「原创化设计建议」不与竞品视觉元素重复。
6. 未出现无法验证的技术结论。

全部 15 页完成后，汇总输出一份竞品调研报告，包含：机制对比表、体验差距清单、BOMB CAT 首版范围建议、原创化设计原则。
