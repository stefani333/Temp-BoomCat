## 3. 现有页面与交互清单

### 3.1 页面与跳转关系

应用没有 URL 路由，使用单一 React 状态机切换页面；刷新页面会回到首页并丢失当前对局。

```text
首页（创建房间）
   ├─ 创建并进入房间 ──→ 房间等待
   └─ 自动演示一局 ────→ 自动演示
房间等待
   ├─ 开始游戏 ────────→ 游戏牌桌
   └─ 返回首页 ────────→ 首页
游戏牌桌
   ├─ 对局结束 ────────→ 结算页
   └─ 各类效果浮层（不切换页面）
结算页
   ├─ 再来一局 ────────→ 房间等待（沿用人数与种子）
   └─ 返回首页 ────────→ 首页
自动演示
   └─ 返回首页 ────────→ 首页
```

## 5. 游戏规则引擎完成度

### 5.1 开局与牌堆

| 人数 | 初始手牌 | 抽牌堆 | 移出本局 | 验证 |
| --- | --- | --- | --- | --- |

| 3 人 | 同上 | 39 | 2 炸弹猫 | 用例通过 |

卡牌总数恒为 56，测试在每局结束后校验手牌、抽牌堆、弃牌堆、移出区与待处理炸弹之和。

### 5.2 回合与攻击

- `advanceTurn` 统一处理回合递减与下一位存活玩家切换，`turnsRemaining` 大于 0 时同一玩家继续。
- `transferAttack` 将下一位存活玩家的回合数直接置为 2，替换而非累加，符合规则 12.1 与 12.9。
- 攻击状态下打出跳过、处理炸弹均只消耗一个回合。
- 淘汰玩家时跳过其剩余回合，下一位从 1 个回合开始（规则未明确，见 C-01）。

### 5.3 卡牌效果

| 效果 | 实现位置 | 验证 |
| --- | --- | --- |
| 拆除 | 炸弹决策与放回流程 | 放回位置、回合结束、不可被休想取消 |
| 休想 | 反制队列与反制栈 | 取消、反制休想、非法抢答拒绝 |
| 恩惠 | 目标选择 + 目标交牌 | 目标自主选牌；空手牌直接结算 |
| 攻击 | `transferAttack` | 两回合、覆盖不叠加 |
| 跳过 | `advanceTurn` | 只结束一个回合 |
| 洗混 | `shuffleInPlace` | 元素集合不变，不结束回合 |
| 预见未来 | 待确认状态 + 视图裁剪 | 仅使用者可见，原序放回 |
| 两张相同猫咪 | 随机抽取 | 目标手牌减一，出牌者加一 |
| 三张相同猫咪 | 名称匹配 | 成功交付，失败退回手牌与弃牌堆还原 |
| 五张不同猫咪 | 弃牌堆选择 | 弃牌堆为空时拒绝 |

### 5.4 炸弹、淘汰与胜利

- 抽到炸弹猫进入待处理状态，不立即进入手牌。
- 有拆除时使用后进入放回位置选择，位置不写入公开事件。
- 无拆除时手牌与炸弹全部进入移出区，不进入弃牌堆。
- 每次淘汰后检查存活人数，仅剩 1 人立即结束并记录获胜者。

### 5.5 隐藏信息

- 视图接口 `getGameView` 只输出本人手牌明细、他人手牌数量、抽牌堆数量、弃牌堆明细与公开事件。
- 预见未来三张牌只在查看者本人的视图中出现。
- 组合抽取、恩惠交牌、炸弹放回位置均不进入公开日志。
- 局限：引擎与完整状态运行在同一浏览器页面内，无法防止开发者工具级篡改；真正的权威边界需服务端化。

### 5.6 模拟玩家

- `nextBotStep` 覆盖回合行动、反制响应、恩惠交牌、炸弹决策、放回位置与预见未来确认。
- 模拟玩家仅读取自己的手牌与公开信息，目标选择依据公开的手牌数量。
- 所有模拟动作都通过 `GameEngine.apply` 校验，没有直接改状态的旁路。

## 7. 工程实现审计

| 审计项 | 结论 | 说明 |
| --- | --- | --- |
| 规则引擎与 UI 分离 | 通过 | `packages/game-core` 不依赖 React；UI 只通过包导出使用 |
| 页面是否直接改状态 | 通过 | 页面只接收 `GameView`；`apply` 调用仅存在于 `App.tsx` |
| 模拟玩家是否走统一引擎 | 通过 | 模拟决策产出 `GameAction`，由同一 `apply` 校验结算 |
| 随机是否统一管理 | 基本通过 | 洗牌、抽牌、随机抽手牌、炸弹放回、模拟决策均使用引擎 `rngState`；仅初始种子缺省使用 `Math.random` |
| 隐藏信息是否泄露 | 本地通过 | 视图裁剪已实现且有测试；同浏览器内存内仍可被开发者工具读取，属服务端化前的已知限制 |
| 非法操作处理 | 通过 | 回合、存活、手牌归属、组合合法性、弃牌存在性、放回范围均有校验 |
| 重复操作处理 | 部分通过 | 引擎支持 `actionId` 幂等，但 UI 未传 `actionId`；本地单机无网络重试，风险低 |
| 异常提示 | 通过 | 引擎错误以底部提示条展示；浮层与按钮禁用表达明确 |
| 错误恢复 | 部分通过 | 模拟玩家动作失败会停止自动推进并提示，但无错误边界与常驻错误状态 |
| 安装、运行、测试、构建 | 通过 | 五项均已实际执行成功 |
| CI | 部分通过 | Pages 构建与部署已配置；浏览器冒烟未纳入 CI |
| 持久化 | 未实现 | 刷新即丢失对局与日志，符合当前单机 MVP 范围 |

补充观察：

- `nextBotStep` 在 UI 定时器中调用时会读取并推进引擎随机状态，实际动作稍后才通过 `apply` 落盘。随机数仍由引擎统一持有，但随机消耗发生在动作提交之前，属于轻微副作用，建议后续把模拟决策改为不消耗随机数或移入引擎动作内。
- 页面无 URL 路由，深链接与刷新恢复不可用，联机阶段需要补充路由与重连恢复。
- 线框预览台使用独立模拟数据，不复用 `game-core`，其作用是视觉与流程预演，不代表真实对局结果。
